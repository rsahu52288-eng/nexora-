3 Project Simulation & Algorithm Implementation

NEXORA features an end-to-end 9-Step Zero-Knowledge Client-Side Cryptographic Pipeline executed whenever a user uploads an asset:

Step 0: File Intake
Header validation, MIME type detection, byte-size calculation.
Step 1: SHA-256 Digest
High-speed cryptographic hash generated via WebCrypto API.
Step 2: Deduplication
Content-addressable check; eliminates redundant cloud storage.
Step 3: Compression
Lossless Gzip stream compression; reduces payload size by ~60%.
Step 4: AES-256 Encryption
Military-grade AES-256-GCM authenticated cipher with 96-bit IV.
Step 5: Chunk Partitioning
Payload sliced into 8 discrete parts with individual sub-hashes.
Step 6: Parallel Upload
Multi-part streaming to Supabase Storage bucket.
Step 7: Verification
Server-side checksum confirmation and tamper verification.
Step 8: Vault Committed
Row inserted to Supabase PostgreSQL; user storage updated.

Algorithm 1: Cryptographic Fingerprinting (SHA-256)

Generates a deterministic 64-character hexadecimal digest representing the file's binary stream:

Digest = HexEncode( SHA-256( ArrayBuffer(File) ) )

Implemented in lib/crypto-engine.ts using crypto.subtle.digest("SHA-256", buffer).

Algorithm 2: Content-Addressable Deduplication (CAD)

Before transmitting file bytes to cloud storage, the system checks if the file digest H_new already exists in the user's database:

IF ∃ H_existing = H_new THEN Duplicate = TRUE → Link Metadata → Bypass Binary Upload

This zero-knowledge deduplication saves user bandwidth and instantly credits duplicate savings in user analytics.

Algorithm 3: Lossless Stream Compression (Gzip Deflate)

Applies the DEFLATE algorithm through the browser's CompressionStream("gzip"):

Savings Percentage = ((Original Bytes - Compressed Bytes) / Original Bytes) × 100

Algorithm 4: Authenticated Zero-Knowledge Encryption (AES-256-GCM)

Encrypts the compressed payload on the client side prior to network transmission:

Ciphertext = AES-GCM-256( Key_256, Nonce_96, Payload_Buffer )

The encryption key is generated client-side and never exposed to intermediate transit nodes in plaintext.

Algorithm 5: Dynamic Multi-Part Chunk Partitioning

Partitions the encrypted buffer into k = 8 uniform blocks:

Chunk_Size = ⌈ Total_Bytes / 8 ⌉, Chunk_i = Slice( i × Chunk_Size, min((i+1) × Chunk_Size, Total_Bytes) )
